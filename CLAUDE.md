## What this is
A personal Chiang Mai trip-planning map. Static site, **no build step, no npm dependencies**. Leaflet 1.9.4 loads from unpkg in `index.html`; `js/app.js` is an ES module that imports `js/data.js`.

## Run / check
- Serve locally: `python3 -m http.server 8000`, then open http://localhost:8000
- Syntax check: `node --check js/app.js && node --check js/data.js`
- Deploy: GitHub Pages from `main` / root (`.nojekyll` is present).
- **Before every deploy commit run `tools/bump-version.sh`.** It stamps `?v=` on the CSS/JS references in index.html and on the local imports in js/app.js and js/sync.js, so phones don't keep running a cached old version. New local imports must use the same `?v=` pattern (all imports of a module need the identical string, or the browser loads it twice).

## Architecture
- **Map:** Leaflet + OpenFreeMap vector tiles via MapLibre GL (`maplibre-gl-leaflet`), drawn with our own style object from `js/mapstyle.js`. CARTO free tiles now need an API key, so don't go back to them.
- **Pins:** `L.divIcon` painted SVGs from `CATS[cat].art` (`js/data.js`) with `--c-<cat>` wash colours. Night = martini glass, Other = quiet flower.
- **State:** `places` array in localStorage key `cm-trip-map-places`. Place shape:
  `{ id, name, cat, note, fav, exact, lat, lng, ideaId, createdAt, updatedAt, tags[], visited, day, order, icon, hours{open,close,closed[]}, price }`. `icon` overrides the category art (keys of `CATS` or `EXTRA_ICONS`); hours are Chiang Mai time (`openStatus`, UTC+7). `exact` = location came from OSM search, coordinates or a Google Maps link (vs. built-in/hand-placed).
- **Phone layout:** no title row on phones (iOS blurs content just under the status bar, which smudged it); the map runs to the top and overlays are offset by `env(safe-area-inset-top)`.
- **Phone navigation (≤860px, not view-only):** a bottom bar `#tabbar` with Map (Places / Near me), Plan (Today / All days), Add, Money (Shared bills / My spending switch, last one remembered) and Trip (`trip` view: essentials card, look, sync, offline, share, backup). The header buttons and sync footer are hidden there. `currentTab()` derives the tab from `view`/`listMode`; `goTab()` switches; `decoratePanel()` runs after every `renderPanel()` to mark the tab, swap in the Money switch and relabel back buttons (`‹ Trip`, `‹ Today`…). Desktop keeps the header buttons and four list tabs.
- **Controls (desktop):** header has only **Add a place** (popover: search / paste link / drop a pin) and **Menu** (`openMainMenu`: essentials, shared bills, spending, sync, offline, share, back up, restore). The map has one **Layers** button (`#layersBtn`: transport spots, ideas). All three use the shared `openPop()` popover (`#pop`).
- **Panel views:** `essentials` | `bills` | `spend` | `sort` | `offline` | `share` | `sync` (trip code) | `list` | `detail` (place card with Google Maps/Waze links) | `edit` (uses `draft`) | `preview` (search or idea result before adding).
- **Search order:** pasted coords/Google Maps link → your tags (`#tag` filters) → your pins → built-in `DIR` matches → Photon (OSM) results, debounced 300 ms, filtered to 150 km around Chiang Mai.
- **Sync:** `js/sync.js` calls Supabase RPCs `trip_get`/`trip_put` (see `supabase/setup.sql`) over plain fetch. Rows keyed by (trip code, pin id); newest `updatedAt` wins; deletes are tombstones (`cm-trip-map-deleted`); `cm-trip-map-known` tracks what the server has. Trip code lives in localStorage only; `#join=CODE` links a device. Always bump `updatedAt` via `savePlace`.
- **Share links:** short Google Maps links are resolved by the Supabase Edge Function `unfurl` (`supabase/functions/unfurl/index.ts`, deployed by hand with JWT verification off); the app then parses coords/name from the full URL (`resolvePasted` in app.js). Google Places search is deliberately not used: Google's terms forbid Places content on a non-Google map.
- **List import:** `unfurl` also detects shared saved-list links and reads Google's unofficial `maps/preview/entitylist/getlist` feed (list name + each place's name/coords/note). The `import` panel view lets the user tick places and fix guessed categories (`guessCat`); pin ids are `g<cid parts>` so re-imports don't duplicate. The user chose this knowing it's unofficial and may break.
- **List modes (tabs):** `listMode` = today | type ("Places") | near | days; switch with `applyListMode()`. Category/tag/visited filters live in a collapsible drawer (`filtersOpen`, Filter button with a count).
- **Today:** `todayInfo()` places today in the trip (Chiang Mai time, needs `trip.start`); `todayBody()` shows the next unvisited stop as a card with directions and "Done, next stop", then the rest. The app opens on Today when it is a trip day with stops, and the map shows only that day (`dayFocus`).
- **Travel times:** `js/routing.js` asks routing.openstreetmap.de (foot + car) for a day's ordered stops; legs ≤1.3 km show as a walk, longer as a drive; the car geometry is drawn as the day's route. Cached in memory + localStorage `cm-trip-map-routes`; falls back to straight lines and "x apart".
- **Quick sort:** places with `cat: 'other'`, no `icon` and `sorted: false` (imports the type guesser missed) get a card on the Places tab; the `sort` view sets type (+ optional day) one tap each.
- **Trip essentials:** `js/essentials.js`, localStorage `cm-trip-map-essentials` (stay + Thai address with a full-screen "Show to driver" card, flights, bookings, emergency numbers). Synced AES-GCM-encrypted under an HKDF-derived namespace of the trip code (row `__ess`), so trip-code devices get it and view-only links never do. Location starts only from the locate button (`startLocate`). Days use `p.day` + `p.order`; `dayFocus` filters the map and `renderRoute` draws the dotted path.
- **Trip settings:** `trip = { days, start, titles }` (localStorage `cm-trip-map-trip`) syncs as one extra row with id `__trip`; `getPlaces`/`applyRemote`/`loadViewOnly` split it out. Days tab: add/remove/rename days, start date → real dates + Today, `daypick` view to tick places for a day, day colours (`dayColor`), badges and per-day routes.
- **Quick-action menu:** `⋯` (`data-more`) on list rows opens `#qmenu` (`openMenu`), a fixed popover appended to body; closes on outside tap, Escape, scroll, resize. Deletes go through `deleteWithUndo` (toast with Undo).
- **iPhone home-screen app:** separate storage from Safari. `showJoinHint()` shows a Paste-code card when running standalone without a trip code; `pasteAndJoin()` reads a code or `#join=` link from the clipboard.
- **Transport layer:** off by default; the bus button (`#trBtn`, `toggleTransit`) loads `data/transit.json` (OpenStreetMap snapshot: 5 hubs, taxi stands, ~225 bus stops). Hubs show at any zoom (names from z13), taxi stands from z14, bus stops as small white bus-sign icons from z15 within the view (the user found plain dots confusing). `#trLegend` is the on-map key; the tapped item gets `.sel` and its name instead of a preview pin. Taps open the `preview` card (`source: 'transit'`).
- **Opening hours are manual only.** Auto-fill was investigated (Nov 2026): OpenStreetMap had hours for 0 of the user's 14 places, and Google's terms bar Places data on a non-Google map. Don't build an OSM auto-fill expecting it to work.
- **Offline:** `sw.js` (network-first page, cache-first versioned assets/libs/tiles, tile index network-first). `saveOffline()` pre-fetches ~200 tiles for the city (z10–14) and province (z8–11). The in-app preview browser can't register service workers, so test offline on a real browser.
- **View-only:** `#view=CODE` sets `viewOnly`: pins load from `trip_view_get` (`supabase/share.sql`), nothing persists, editing UI is hidden by `.viewonly` CSS.
- **Spending log (private):** `js/expenses.js` owns the `spend` panel view (header **Spend** button). Entries `{ id, amount, cur: THB|MYR, what, cat, date, shared, plan, createdAt, updatedAt }` (`shared` = bill split in two, half counts; `plan` = estimate, not spent; a category's projection is max(spent, planned)) in localStorage `cm-trip-map-expenses` (+ `-set` for the ฿-per-RM rate). Deliberately **never** in the trip-code sync, the pins Export or view-only maps: the map is shared, spending is per person. Don't route it through `sync.startSync` or `places`.
- **Shared bills (the two travellers):** `js/bills.js`, panel view `bills` (Menu → Shared bills). Bills `{ id, kind: bill|settle, amount, cur, what, cat, date, payer: 0|1, split: even|p0|p1|exact, share0 }` in localStorage `cm-trip-map-bills`; the two names and a shared ฿-per-RM rate are the `__set` row (`-set`). Names are typed in the app, never hard-coded (public repo). Each device stores which person uses it (`cm-trip-map-bills-me`, the "You: …" chip). Balance is shown in baht with a rough RM line. Synced per row, AES-GCM-encrypted under an HKDF-derived namespace of the trip code (prefix `b`), so both people get it and view-only links never do. The private Spending log reads this device's person's part through `bills.myShares()` (`spend.setShares`), shown read-only there; nothing is copied into the spending store. The old "split in two" tick now only applies to planned estimates; real split entries get a one-tap move into Shared bills.
- **Spending sync (one person's devices):** optional, in `expenses.js`. A separate 24-char spending code (`cm-trip-map-expenses-code`, link `#spend=CODE`) is run through HKDF to get (a) the namespace sent as `p_trip` to the same `trip_get`/`trip_put` RPCs and (b) an AES-GCM key. Rows are `{v,iv,ct}` ciphertext (the rate is row `__rate`), so the server never sees the code or readable entries. Same newest-wins/tombstone merge as pins (`-deleted`, `-known` keys). Needs a secure context (https or localhost) for WebCrypto.
- **Spending budget and pre-fill:** trip budget (MYR) lives with the rate in `cm-trip-map-expenses-set` and syncs in the `__rate` row. `#addspend=<base64url JSON {budget, items}>` adds entries from a private link (fixed ids, so no duplicates); never hard-code personal amounts in this public repo.
- **Keep-awake:** `.github/workflows/keep-supabase-awake.yml` pings `trip_get` every 3 days.
- **Export/Import:** JSON `{ app, version, exportedAt, places }`; import merges by `id`.

## Style
- **Painted look (17 Nov 2026).** The user found the old pastel look dull and approved this direction from mockups. The previous look is the git tag `before-new-look` (also on GitHub). It is the block "Painted look" near the end of `css/style.css` plus:
  - Palette: lighter paper, darker ink, four strong paints as tokens (`--gold`, `--saffron`, `--red`, `--teal`), stronger `--c-<cat>` colours and `DAY_COLORS`. Strong colours stay off big surfaces (`.xtotal`, `.tnote.good`, `.joinhint`… use a thinner `color-mix`).
  - Map: `PAINT` in `js/mapstyle.js` is straw land, terracotta town, dark forest, clear blue water. `LANDMARKS` (`js/data.js`, art in `LANDMARK_ART` in app.js) are painted drawings shown between `min`/`max` zoom and skipped within 56px of a user pin (`renderDecor`, also called from `renderMap`). Desktop map has an ink-and-gold frame; `.compass` is decorative.
  - Sky banner: `.sky` in `index.html` at the top of the panel, shown only on `list` and `trip` views (`#panel[data-view]`). `data-sky` = dawn | noon | gold | night on `<html>` (`skyPhase()`, Chiang Mai time; the night look always gets night, the day look never does). `.tint` lays a light matching wash over the map. `?sky=dawn|noon|gold` forces one for testing.
  - Cards: list rows are white cards (`--row`); the day shows as a ticket (`.tk`), visited as a round stamp (`.stampv`); day groups look like ticket stubs.
  - Hand-drawn icons: the five tab icons and the search icon are redrawn with a paint patch (`.w` paths, `--w` colour). Other line icons get the `#ink` wobble filter and `.pic` gets an off-register patch. Keep `#ink`/`#wc` filters off anything repeated per list row or inside the sliding sheet's moving parts; they are slow on iPhone.
  - Phone sheet has a torn-paper top edge: two masked strips (`.panel::before/::after`) sitting above the sheet, never a mask on the sheet itself.
- Look: pastel watercolor illustrated map (inspired by hand-painted city maps). Day is the default; the user asked for a night look too (Nov 2026).
- **Day / night:** `themePref` = day | night | auto (localStorage `cm-trip-map-theme`; auto follows the device). An inline script in `index.html` sets `data-theme="night"` on `<html>` before paint. Night tokens are the last block of `css/style.css`; pastel surfaces (`.xtotal`, `.tnote.good`, pressed chips, go buttons…) keep their paper colours at night and re-scope the ink tokens, so add new pastel surfaces to that `:is()` list. The basemap swaps to `nightStyle` (`PAINT_NIGHT` in `js/mapstyle.js`). Since 17 Nov 2026 `PAINT_NIGHT` mirrors the painted day map's contrasts (the user said night lacked the day update): indigo land, warm plum lamp-lit town, distinct green forest/parks, a moonlit blue river lighter than the land, gold roads; night also keeps the desktop ink-and-gold frame and gets light area names with a dark edge (last lines of `css/style.css`). `setTheme(pref, fromButton)` reveals the new look in a circle from the tapped button (View Transitions, skipped for reduced motion) and floats a few lanterns up when night falls. Toggle: Trip tab on phones, last Menu item on desktop.
- Basemap: hand-built MapLibre style in `js/mapstyle.js` (colours in `PAINT`). Paper/wash texture is the `.paper` overlay in CSS.
- Pins are small paintings: `CATS[cat].art` in `js/data.js` (48×48 SVG, ink #4A4036), run through the `#wc` SVG filter defined in `index.html`. Area names (`AREAS`) and decorations (`DECOR`) are painted as non-interactive markers.
- **Small moments** (user likes these; keep each one brief, tied to a real action, and off under reduced motion): lanterns rise at nightfall and petals fall by day (`celebrate()`, on finishing every stop of a day and on settling up), a sun rises when switching to Day, the visited tick lands like a stamp and a must-go heart pops (`fxPin`, one-shot classes `fx-visit`/`fx-fav`), a new pin lands with a ripple, the settle-up balance counts down to zero, stars twinkle by the title at night. Styles are the "small moments" block at the end of `css/style.css`.
- Fonts and hierarchy: Amatic SC only for panel titles; Patrick Hand for things the user named and for buttons (place names, day names); Nunito small caps (`.eyebrow`, `.group h3`, `.ehead`) for section and field labels; Nunito for notes, meta and numbers. Keep to these four roles.
- Place card order: name → status line (open, distance, day) → directions → visited/plan → notes, hours, tags → "Edit details" link.
- Tokens are CSS custom properties at the top of `css/style.css`; `--wobble` is the hand-drawn pill radius.
- Phone (≤860px): full-screen map, panel is a bottom sheet (`#panel[data-sheet=peek|half|full]`, `setSheet()` in app.js).
- **Bottom sheet mechanics (Nov 2026, modelled on Google Maps at the user's request):** the panel is always full height and slides with `transform` (`placeSheet()`); the hidden part is given back as `padding-bottom` once it settles so the list scrolls to its end. Touch handling is on `#panel` with touch events, decided on the first `touchmove` (the only moment iOS lets a page take a gesture): the whole sheet drags; the list scrolls only at `full`; pulling down at `scrollTop 0` lowers the sheet; a sideways swipe changes tab (Map ↔ Plan ↔ Money ↔ Trip; the user chose whole tabs, not the inner switches) or, on an inner screen, a swipe right goes back (`swipeTargets`/`canSwipe`/`swipeStart`/`swipeMove`/`swipeEnd`). The content follows the finger; it goes past 30% of the width or on a flick, otherwise springs back; at the first/last tab it only gives a little. Sideways moves inside rows that scroll sideways, on form fields, and on the edit form, list import, day picker or any `view.edit` form stay native (no unsaved typing lost). Release uses finger velocity (`trail`) to pick the next stop and the slide length. Mouse dragging (narrow desktop window) uses pointer events on the handle, sky banner and title. Don't go back to animating `height` or masking the panel: both made dragging janky on the user's iPhone.
- Declutter: built-in ideas are off by default; pins closer than ~38px bundle (`clusterPins`, off at zoom ≥17); every pin name stays visible and `declutterLabels()` moves it right → below → left → above to avoid overlaps (only idea names may hide); `shortName()` trims long names on the map; icon size scales with zoom via `--ps`.
- The map needs requestAnimationFrame, so it stays blank in a hidden/background browser tab; that's not a bug.

## Testing notes (learned the hard way)
- **Never test against the real Supabase with a trip code.** Test pins once got uploaded to the live project. To test sync, bills or essentials: temporarily point `SUPABASE_URL` in `js/config.js` at a small local mock of `trip_get`/`trip_put` (a Python `http.server` subclass with CORS), use two origins (`127.0.0.1:PORT` and `localhost:PORT`) as two devices, then restore `js/config.js`, clear both origins' localStorage and confirm `git diff js/config.js` is empty before committing.
- `node` is not installed on this Mac, so the syntax check above can't run; load the page and read the console instead. Python `urllib` fails on SSL here; use `curl`.
- The in-app preview browser can't register service workers, pauses animations and gives stale screenshots while its pane is hidden. `requestAnimationFrame` may not fire there at all, so the basemap stays blank until the map is nudged (`__map.panBy([1,0])`) and CSS transitions never finish: to test the sheet, dispatch synthetic `TouchEvent`s, fake `timeStamp` with `Object.defineProperty`, and force `panel.style.transition='none'` before each gesture.
- Browsers cache CSS/JS by `?v=`, so run `tools/bump-version.sh` after edits even for local testing (it only changes once a minute). `?debug` exposes `window.__map`. Animations and the iPhone status bar area can only really be judged on the user's phone.
- Workflow the user expects: describe or mock up first when they ask for ideas, build and test locally, then ask before publishing (`tools/bump-version.sh`, commit, push, wait for GitHub Pages to serve the new `?v=`).
